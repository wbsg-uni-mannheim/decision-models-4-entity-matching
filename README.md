# EMDecision

Code and data for the paper *Decision Models for Entity Matching*. The paper evaluates decision models, LLM APIs that return a match probability instead of text, on eight entity matching benchmarks, and compares them with a generative LLM, Ditto, and published results.

## Repository layout

| Folder | Content |
|---|---|
| `src/` | Shared code: request protocol (`protocol.py`, `run.py`), 12-prompt study (`prompt12.py`), input serialization and robustness (`inputs_study.py`), validation thresholds (`valsel.py`, `valsel_eval.py`), cascade and ensemble escalation (`escalation.py`, `cascade_eval.py`, `escalation_eval.py`), reference LLMs on all test pairs (`reference_rest.py`, `reference_eval.py`, `qwen38_baseline.py`), error analysis samples and evaluation (`errcat_f0_sample.py`, `errcat_census_sample.py`, `errcat_eval.py`, `errcat_census_eval.py`), data preparation (`prepare.py`). |
| `runners/` | Slurm runners and batch scripts used for the paid runs, with their offline tests. Each runner freezes a manifest before any request and checks it before execution. |
| `configs/` | Frozen manifests of every study, the selected prompt per model and benchmark (`inputs_prompt_selection_20261019.json`), and the rules derived by GPT-6 Astra (`learned_rules.json`). |
| `data/<benchmark>/` | Frozen splits of the eight benchmarks: `test.json`, `valid.json` (full validation set used for threshold tuning), `rules_train.json` (100 labeled training pairs for the Astra rules), `escalation.json` (test pairs escalated to the ensemble), `reference_rest.json` (the remaining test pairs, answered by the ensemble members as reference LLMs), `escalation_sample.json` (500-pair pilot). |
| `error_analysis/` | Error codebook: the 26 categories generated by GPT-6 Astra and the frozen 8-group version used in the paper. |
| `results/` | Aggregated results of the cascade, the ensemble escalation, the error analysis, and the reference LLMs (`reference_eval_20261022.json`: F1 of GPT-6.1 Sol, Claude Opus 5.5, Gemini 4 Argon, their majority vote, and Qwen3.8-27B on all 30,225 test pairs; `opus_batch_vs_live_sample1000_20261022.json`: agreement of the Opus batch answers with normal requests on 1,000 pairs). |
| `docs/` | Exact texts of the twelve prompts and the Astra rules (`PROMPTS.md`), full results of the 12-prompt study, codebook documentation. |
| `tests/` | Offline tests of the shared code. |

The raw API responses of all runs (one JSON line per pair with request hash, response, usage, and cost) are attached to the GitHub releases of this repository as one archive per study.

## Benchmarks

Abt-Buy, Walmart-Amazon, DBLP-ACM, and DBLP-Scholar (DeepMatcher splits), WDC Products (80% corner cases, 100% unseen entities), Dn7 Walmart-Amazon (Papadakis et al., ICDE 2024), billiger.de Products (80% corner cases, 100% unseen, German), and Semi-HETER (Machamp). `src/prepare.py` derives the frozen splits from the original benchmark files, which are not redistributed here. Please refer to the original benchmark releases for their licenses.

## Reproducing runs

Python 3.10. The runners read the OpenRouter key from `OPENROUTER_API_KEY` and the OpenAI key from `OPENAI_API_KEY`, or from `.secrets/source.env` (not part of the repository). Every paid runner needs an approval file and checks a shared budget ledger before sending requests. Run the offline tests with

```bash
PYTHONPATH=src:runners python -m unittest discover -s tests
```

## Not included

The packages of the blind human audit and the mapping from error cases to the models that made them are withheld until the audit is complete. Internal approval records, the budget ledger, and job logs are not part of the release.
